# 貼り付け仕様（原文）

後続指示による変更：10ステージ案は **4つの舞台を順次解放し、各舞台を4通常区画＋第5区画のボスで構成** に変更。足場・敵を毎挑戦ランダム生成。「10回に分ける」という開発進行の意味ではない。

現在の2.5Dアクションローグライトを、以下の仕様に沿って大幅に改良してください。

目的は、短時間でも「大量撃破の爽快感」「成長と報酬の期待」「次のステージへ挑戦したくなる気持ち」を得られるゲームにすることです。

既存コードと実装済みの機能を確認し、有効な部分を活かしながら、設計・実装・テスト・バランス調整まで進めてください。提案だけで終わらず、ブラウザで遊べる状態まで完成させてください。

━━━━━━━━━━━━━━━━━━
1．最重要変更：短いステージを選んで遊ぶ
━━━━━━━━━━━━━━━━━━

現在の長い連続プレイ方式を、ステージ選択・順次解放方式へ変更してください。

・最初はステージ1のみ挑戦可能。
・ステージをクリアすると、次のステージが一つ解放される。
・解放済みのステージは、いつでも選択して再挑戦できる。
・クリア後は報酬と結果を表示して一度区切る。次のステージへ強制的に進めない。
・「次のステージ」「同じステージに再挑戦」「ステージ選択へ」を用意する。
・敗北しても、解放状況や獲得済みの恒久報酬は失わない。
・初期構成は既存の10ステージを活かす。各ステージの内容と時間は再設計してよい。
・通常ステージは初見で約2〜3分、ボスステージは約3〜5分を設計目標とする。
・移動するだけの区間、不要な待ち時間、同じ戦闘の繰り返しを減らす。
・タイム制限を必須にせず、短く遊び終われる内容量にする。

ステージ選択画面では、次の情報を簡潔に表示してください。

・ステージ名と、その場所が伝わるビジュアル
・挑戦可能／未解放／クリア済み
・通常戦／ボス戦などの特徴
・目安時間
・初回クリア報酬
・自己ベストのスコア、ランク、クリアタイム
・次に挑戦するおすすめのステージ

未解放ステージは、解放条件を一目で理解できるようにしてください。

2．成長と保存：短い挑戦でも報酬が無駄にならない
━━━━━━━━━━━━━━━━━━

「その挑戦中だけの成長」と「次回以降も残る獲得物」を整理し、プレイヤーにわかりやすく伝えてください。

基本方針：
・ステージ解放、初回報酬、獲得したレアスキルの解放、自己ベスト、設定は保存する。
・HP、MP、経験値、挑戦中のスキル強化などは、各ステージ開始時に初期化する。
・各挑戦は十分なHP・MPで開始し、前回の消耗を持ち越さない。
・既存ステージを周回しないと次へ進めないような、必須の稼ぎ作業は作らない。

ステージごとの初期化で宝箱の価値が失われないよう、次の仕組みを基本にしてください。

・宝箱で獲得したレアスキルは、次回以降の持ち込み候補として解放される。
・出発前に、解放済みのレアスキルから一つを選んで持ち込める。
・初期装備は基本剣技＋選んだ持ち込みスキル。必殺技は別枠で最初から所持。
・手動スキルはスロットを使い、自動技・常時効果はスロットを使わない。
・持ち込みの強さとステージ内成長を調整し、序盤が完全な作業にならないようにする。
・出発画面では前回の選択を記憶し、毎回選び直さなくてよいようにする。

保存データには形式のバージョンを持たせ、既存データを扱う際は互換性を考慮してください。保存不可や破損時にも白画面にせず、遊べる状態を保ってください。

━━━━━━━━━━━━━━━━━━
3．序盤：回避を要求しすぎず、大量撃破を楽しませる
━━━━━━━━━━━━━━━━━━

・序盤は弱い敵を多めに出し、通常攻撃や技でまとめて倒せるようにする。
・敵の数が多くても、同時に攻撃する敵は少なくする。
・回避に慣れていないプレイヤーでも、移動と攻撃で楽しめる難易度にする。
・進行に合わせて盾、射手、突進、支援役などを段階的に追加する。
・まとめて倒す弱い敵と、対応を考える強い敵を分ける。
・敵の耐久力は「通常攻撃で何発、得意技で何発で倒せるか」を基準に調整する。
・強敵を大量に並べることや、HPを増やすことだけで難易度を上げない。

序盤の体験では、次の流れを自然に作ってください。

移動する
→ 自動攻撃で敵を倒す
→ 群れを技でまとめて倒す
→ レベルアップして選ぶ
→ 成長した強さを実感する
→ 宝箱を獲得する
→ 次のステージが解放される

━━━━━━━━━━━━━━━━━━
4．経験値とステージ内の成長
━━━━━━━━━━━━━━━━━━

・序盤は早めに最初のレベルアップが起こるようにする。
・短い一ステージの中でも、複数回の成長と戦い方の変化を感じられるようにする。
・敵の数、獲得経験値、必要経験値、戦闘時間をまとめて調整する。
・レベルアップは経験値がたまったタイミングで成立させる。
・4択で頻繁に戦闘が止まりすぎないよう、成長回数と選択時間を調整する。
・必要なら選択を短時間保留できるようにし、未選択の報酬を見失わない表示にする。
・経験値獲得、バーの充填、レベルアップを視覚と音でつなげる。

レベルアップの4択は、現在の装備や成長状況を考慮しながらランダムにしてください。選べない候補、意味のない候補、同一候補の重複を避けてください。

━━━━━━━━━━━━━━━━━━
5．宝箱：クリアしたくなる特別な4択
━━━━━━━━━━━━━━━━━━

宝箱を、ステージクリアの中心となる報酬にしてください。

・クリア後に宝箱を開き、少しレアだと感じられるスキルや強化をランダム4択で提示する。
・通常のレベルアップ報酬とは、候補の特別さと演出で差をつける。
・新しい攻撃方法、技の進化、特徴的な自動技など、遊び方が変わる報酬を重視する。
・レア度は色だけでなく、名称、アイコン、短い説明でも示す。
・開封演出は期待感を持たせつつ、繰り返し遊ぶ際に長すぎないようにする。
・初回クリアは特に価値を感じる報酬にする。
・再クリアでも報酬を得られるが、同じ面の周回だけが最適にならないようにする。
・既に解放済みの候補を選ぶ場合は、得られるものを明示し、無意味な重複にしない。
・報酬候補が不足した場合も、4択が成立する有用な代替報酬を用意する。
・報酬の獲得、保存、次ステージ解放を安全に処理し、連打や再読み込みによる二重取得を防ぐ。

短いプレイでも「今回はこれを手に入れた」と感じられる結果にしてください。

━━━━━━━━━━━━━━━━━━
6．操作と戦闘の気持ちよさ
━━━━━━━━━━━━━━━━━━

・移動速度と操作への反応を軽快に保つ。
・通常攻撃は自動。攻撃対象と届く距離を把握しやすくする。
・回避の名称は「回避」のまま、移動方向への短いステップにする。
・Shiftまたは回避ボタンの長押しで繰り返せる仕様を維持する。
・無敵中と無敵終了後を見分けやすくし、長押しだけで常に安全にはならないようにする。
・回避成功からの反撃、大量撃破、強敵撃破に強い手応えを持たせる。
・技は再使用のたびに押すだけにならないよう、状況に応じた使いどころを作る。
・自動技は手動操作を助け、プレイヤーが判断する意味を残す。
・命中、盾に弾かれたとき、回避成功、撃破を異なる動きと音で表現する。
・入力の取りこぼし、不要な硬直、演出による操作の重さを減らす。
・キー変更とスマホでの押しやすさを整える。

最初は移動と自動攻撃を体験させ、回避、技、必殺技を必要な場面で順に覚えられるようにしてください。

━━━━━━━━━━━━━━━━━━
7．敵の予兆と役割
━━━━━━━━━━━━━━━━━━

・攻撃の予告、発動、残留攻撃を明確に区別する。
・予兆と実際の当たり判定を一致させる。
・薄い外周と、内側から広がって濃くなる表示などで、発動までの進行を伝える。
・弾を撃つ攻撃は弾道中心、範囲攻撃は面中心の表示にする。
・予兆の重なりと攻撃開始の順序を管理し、逃げ道を残す。
・主人公の技やエフェクトで重要な予兆が隠れないようにする。

敵ごとの対応を、見た目と動作で理解できるようにしてください。

・盾持ち：背後や攻撃後の隙を狙う。
・射手：弾道を避けて接近する。
・突進役：横へ避けて反撃する。
・支援役：優先して倒す意味がある。

盾持ちは正面からのダメージを10分の1に軽減し、正面攻撃を受けると敵自身が押し返されるようにしてください。

━━━━━━━━━━━━━━━━━━
8．スキル・装備・必殺技
━━━━━━━━━━━━━━━━━━

・スキルは「単体向き」「群れ向き」「守り」「自動」など、役割を一目で伝える。
・強化前後、装備先、現在の主力、組み合わせの利点を簡潔に示す。
・種類の多さを活かしつつ、似た用途の候補を整理する。
・新しい手動技は空きスロットに自動装備する。
・満杯の場合は、現在の技と比較しながら交換先を選ばせる。
・交換しない選択も用意する。
・自動技と常時強化はスロットを使わない。
・任意の装備変更は出発前または戦闘後に行う。

必殺技：
・最初から所持し、装備枠を使わない。
・戦闘行動でゲージをため、専用ボタンで発動する。
・4択に「必殺技強化」「チャージ」を含める。
・専用カットインと主人公の青い発光を入れる。
・一定時間、被ダメージ半減、与ダメージ増加、移動速度増加。
・ゲージの増加理由、発動可能状態、効果の残り時間をわかりやすくする。
・短い通常ステージでも、適切に戦えば使う機会が生まれる蓄積速度にする。
・群れの出現、ボスの隙、危機脱出など、使用タイミングを選ぶ楽しさを作る。

━━━━━━━━━━━━━━━━━━
9．ボスと地形
━━━━━━━━━━━━━━━━━━

・ボスステージは登場を明確にし、基本は1対1にする。
・HPバーは画面上に派手に、枠なしで表示する。
・ボスは十分な耐久力と重量感を持たせる。
・HP半分で本性を現し、姿勢、見た目、動き、攻撃が変化する。
・突進や跳躍など、戦場全体を使う技を追加する。
・移動技の進路や着地点を予告し、発動後に反撃できる時間を作る。
・HPを増やすだけで長期戦にせず、弱点、装甲破壊、大きく削れる反撃機会を設ける。
・ボスごとに固有の攻略上の特徴を持たせる。
・遮蔽物、誘導先、安全地帯などで、移動先を選ぶ意味を作る。
・遠くへ移動したボスを追い続けるだけの展開を避ける。

ステージは背景の色だけでなく、地形、敵の組み合わせ、戦闘の展開に違いを出してください。ただし、狭い通路や装飾によって移動の快適さを損なわないようにしてください。

━━━━━━━━━━━━━━━━━━
10．グラフィックと静・動の演出
━━━━━━━━━━━━━━━━━━

・剣士の構え、踏み込み、腰のひねり、振り抜き、足運びを改善する。
・主人公に勇者らしい力強さを持たせる。
・必殺技のカットインは、通常キャラクターを拡大するだけでなく、専用の構図や描画を用意する。
・ボスは身体のつながり、重心、着地、予備動作で巨大さを表現する。
・技ごとに動き、音、発動速度、衝撃の強さを変える。
・光だけを増やさず、キャラクター本体と動作の質を高める。
・通常時は控えめ、決め技は豪華、撃破後は静かにする。
・背景は「どんな場所で戦っているか」が伝わる構図にする。
・重要な敵、主人公、予兆が背景に埋もれないようにする。

11．UI・UXと戦闘後の流れ
━━━━━━━━━━━━━━━━━━

・UI、文字、アイコン、色、装飾を世界観に合わせて統一する。
・HP、危険、攻撃対象、技の準備完了を把握しやすくする。
・重複表示、不要な数値、大きすぎる告知を減らす。
・範囲などの内部数値は、「広範囲」「さらに広範囲」など理解しやすい表現にする。
・4択は短い説明で判断できるようにし、詳細は必要な人が確認できる形にする。
・スマホでは指が画面を隠すことを考慮し、ボタンの配置と操作頻度を調整する。
・画面揺れ、閃光、ダメージ数字、演出量を設定できるようにする。
・カットインや開封演出は、繰り返し遊ぶ際の短縮も考慮する。

クリア後の流れは、次を基本にしてください。

撃破と勝利を実感する短い演出
→ 宝箱の特別な4択
→ 結果と次ステージ解放
→ 次へ挑戦／再挑戦／ステージ選択

回復、購入、装備比較などを行う場合は、戦闘後の画面へまとめてください。毎回の装備確認は残しつつ、「この装備で出発」を最短操作にしてください。

各ステージ開始時にHP・MPを初期化する新方式と矛盾する回復販売は、そのまま残さず再設計してください。ポーションは出発準備など、戦闘外で使える明確な用途を持たせ、購入した物が無駄にならないようにしてください。

━━━━━━━━━━━━━━━━━━
12．結果・ゴールド・再挑戦
━━━━━━━━━━━━━━━━━━

・結果に総合スコア、ランク、クリアタイムを表示する。
・ステージごとに自己ベストを記録する。
・ステージ間で敵数や時間が異なることを考慮してランク基準を調整する。
・ゴールドは報酬と購入資源として役立てる。
・購入で使ったことが不利にならないよう、スコアには所持金ではなく、その挑戦で獲得したゴールドを使う。
・初回報酬と再挑戦報酬を明確にする。
・敗北時は「突進への被弾が多かった」など、次に変えられる短いヒントを示す。
・再挑戦までの操作を短くし、装備設定を必要以上にやり直させない。

13．実装・検証の進め方
━━━━━━━━━━━━━━━━━━

まず現在の実装を確認し、要件ごとに「実装済み」「改善が必要」「新規実装」を整理してください。その後、依存関係を踏まえて一つずつ実装・検証してください。

優先順：
1. ステージ選択、順次解放、保存、短い挑戦の流れ
2. クリア宝箱の4択と、次回に役立つ報酬
3. 序盤の敵数、経験値、成長テンポ
4. 操作、攻撃予兆、戦闘の手応え
5. スキル、ボス、グラフィック、演出、UIの磨き込み

検証すること：
・未解放ステージへ通常操作で進めない。
・クリアすると次が一つ解放され、敗北では解放されない。
・解放済みステージを再挑戦できる。
・再読み込み後も進行と報酬が保存される。
・報酬の連打や再読み込みで二重取得しない。
・持ち込みスキルと挑戦中の成長が正しく分かれている。
・手動技、自動技、満杯時の交換が正しく動く。
・序盤が回避必須にならず、成長と大量撃破を楽しめる。
・予兆と当たり判定が一致し、エフェクトに隠れない。
・ボスが短い挑戦の時間目標に収まり、単調な耐久戦にならない。
・PCと狭いスマホ画面で、操作部品や選択画面が重ならない。
・保存不可やエラー時に白画面にならない。
・不要な描画と処理を減らし、重要な動作と演出に処理を使う。

自動テストの成功と、人間が感じる楽しさ・難易度は区別してください。実際の画面を確認し、初見プレイやスマホ実機で確認できていない項目は、未検証として記録してください。
